# Managing dispatch jobs

A job lives in **one** file, `.ai/dispatch/AGENT_N_<THEME>.md`. Its leading ```yaml block is the
machine state; `DISPATCH_LOG.md` is the human index and closure surface; `.ai/CONTEXT.md` lists
only what is open *now*. All three must agree — a job that is `done` in yaml but open in the log
(or the reverse) is exactly the drift `--audit` exists to catch.

Run the tool as `.venv/bin/python scripts/dispatch/dispatch_state.py …` (call it `DS` below).
`.ai/dispatch/CLAUDE.md` mentions `pnpm dispatch:*` — there is no pnpm wrapper here; use the
script. Never edit the yaml block with sed/regex and never hand-edit `_DISPATCH_STATE.md`
(regenerated by `--set/--new`, the pre-commit hook and the Stop hook).

## Open a job

1. **Id**: next number after the highest existing one —
   `ls .ai/dispatch | grep -oE '^AGENT_[0-9]+' | sort -t_ -k2 -n | tail -1`. Ids have collided
   before (two `AGENT_83_*`); check the number is free, including `deferred/`.
2. **Level**: from `docs/harness/level_rubric.md`. Level 3 (migration, secrets, mesh/worker code,
   agent autonomy, destructive ops, >~5 files or crossing a service boundary, operator-flagged)
   needs **operator approval before execution** — author it `ready`, don't start it.
3. **Create**: `DS --new AGENT_<N>_<THEME>` (upper snake case). It writes the yaml block and a stub.
4. **Body**: replace the stub (keep the yaml block) with the section shape from
   `docs/harness/packet_template.md` — header lines (Level/Type/Authored/Depends on/Branch),
   "Read this first", Why, TASK, ACCEPTANCE (proof, not vibes), RESERVED DECISIONS, SCOPE OUT,
   TRAIL, Milestone checklist, Closure. `docs/harness/generators/draft_packet.md` is the drafting
   procedure. ACCEPTANCE is the part reviewers hold the worker to — make each item observable.
   **If the job replaces, unifies, migrates or retires anything** (a new path beside an old one, a
   flag cutover, a second store/reader), add ONE ```` ```arch-contract ```` YAML block stating the end
   state: the names the design deletes (`retired`), layering bans (`forbidden_in`), and store
   ownership (`stores`). Copy names from the design's delete list; do not invent them. Scope it to
   every area the old path lives in (worker, gateway, scripts, prompts), not only the area being
   edited. Format + semantics: header of `.claude/skills/architecture-pathway-audit/scripts/contract_check.py`;
   examples: `.claude/skills/architecture-pathway-audit/benchmark/history/*.yaml`. A stage that
   legitimately leaves something (e.g. a shim until the next stage) gets a `waivers:` entry with a
   reason, never a silent omission.
5. **Dependencies**: `DS --set AGENT_<N>_<THEME> depends_on '["AGENT_94_SYSTEM_ONE_CORE_DELIVERY_SCORECARD"]'`
   (values are written raw — pass yaml literals).
6. **Ledger**: add one row at the **top** of the DISPATCH_LOG Index table, one line only:
   `| A<N> | \`AGENT_<N>_<THEME>.md\` | <YYYY-MM-DD> | <level> | ready | **<headline>.** <one-paragraph why/what> |`
7. **CONTEXT.md**: add a row to "Active Work" only if it is a current priority.
8. Commit docs-only straight to `main` (`docs(dispatch): open A<N> …`).

## Update status

`DS --set <job> status active|blocked|done|dead` (bumps `updated_at`, re-renders). Set `owner`
when someone picks it up. `DS --resolve-blocks` flips `blocked` jobs whose deps are done *and*
that opted in with `auto_unblock: true`.

## Close a job

Only on evidence (see `reviewing-worker-deliveries`) — a closure without proof is flagged
`CLAIMED_DONE_NO_PROOF` by the audit.

1. Append the closure to the **same packet** (never a sibling `.closure.md`), per
   `docs/harness/generators/closure_summary.md`:
   ```
   ### <TASK> — <SHIPPED | PARTIAL | BLOCKED> (<YYYY-MM-DD>)
   **What changed:** one line per file
   **Verification:** exact commands + results
   **F-tag outcomes:** [Fn] → fixed | accepted | no change needed
   **What follows / continuation plan:** …
   ```
   Tick every Milestone box that is actually true; leave the rest unticked and say why.
2. State: `DS --set <job> evidence '["tests/test_x.py","docs/y.md"]'` (paths must exist),
   `DS --set <job> results_ref 'DISPATCH_LOG.md#A<N>'`, `DS --set <job> status done`.
   If the packet has an `arch-contract`, `status done` runs the checker at `HEAD` and is **refused**
   while any violation remains (it prints file:line for each). Do the missing work, or add a waiver
   with a reason and surface it to the operator. Never delete or weaken the contract to get past it.
3. Ledger row Status cell → `done — PR #<n> \`<sha>\`` (still one line); add the key caveat to
   the one-liner if there is one.
4. CONTEXT.md: **remove** the job's Active Work row and any shift note it supersedes — no ✅ rows.
5. `DS --audit --strict` must exit 0 (or every remaining gap is explained), then commit to `main`.

## Audit

`DS --audit` is the honest queue: open jobs, `STALE_<n>d` (active >14 days untouched),
`MISSING_STATE`, `BAD_STATUS`, `CLAIMED_DONE_NO_PROOF`. When the log and the audit disagree,
the git history decides — then fix whichever is wrong.
